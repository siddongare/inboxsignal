## ⚡ Executive Summary

**92% of B2B cold emails fail not because of spam filters or deliverability, but due to acute cognitive friction within the first 3 seconds of executive review.**

Executive buyers scan incoming messages with a rapid filter:
1. **Generic Feature Dumps:** Explaining what a product does rather than articulating acute executive pain.
2. **Surface Personalization Theater:** Quoting recent college degrees or LinkedIn profile headlines without contextual relevance.
3. **Premature Asks:** Demanding 30 minutes on a VP's calendar before establishing any credible proof of value.

**InboxSignal** is a diagnostic engine for sales leaders, founders, and SDRs. Engineered with a haute architectural aesthetic inspired by **Issey Miyake** and **Mikalai** (Electric Acid Lime `#D4FF00` on deep obsidian `#060709`), it transforms subjective copy reviews into mathematical, deterministic diagnostics.

## 📐 Core Capabilities

### 1. Radial Signal Index (0–100)
A real-time radial composite meter calibrated across 4 foundational dimensions:
- **Clarity & Readability (25%):** Word velocity (<110 words), paragraph rhythm, and executive mobile scannability.
- **Prospect Relevance (25%):** Tight alignment with the buyer's acute business stage, role priorities, and triggering events.
- **Proof & Credibility (25%):** Quantified metrics, named peer customer proof, and zero unbacked superlatives.
- **CTA Friction (25%):** Frictionless closing ask requiring only a 1-word interest reply rather than an immediate calendar booking.

### 2. Forensic Failure Diagnostics
Actionable failure analysis ranked by severity (`Critical`, `High`, `Medium`, `Low`):
- **Failure Mechanism:** Explains the exact cognitive trigger causing an executive to hit *Delete* or *Report Spam*.
- **Actionable Correction:** Step-by-step copywriting directive to eliminate the identified flaw.

### 3. Conversion-Focused Synthesis
- **Side-by-Side Review:** Instant split-view comparison between Original Draft and Synthesized Vector.
- **4 A/B Subject Line Hooks:** Direct, curiosity-based, trigger-specific, and peer benchmark angles.
- **Iterate V2 Pipeline:** Single-click transfer of the generated rewrite back into the composer to iterate successive drafts and track score gains.

### 4. Multi-Touch Cadence Sequencing
- **Day 3 Cadence (Soft Bump):** Low-friction context touch that provides fresh perspective without generic "checking in" filler.
- **Day 7 Cadence (Value Pivot & Polite Breakup):** Courteous takeaway closing the loop while preserving pipeline opportunity.

### 5. Web Audio Tactile Soundscapes
- Zero-dependency physical micro-interaction feedback synthesized dynamically via the **Web Audio API** (crisp mechanical tactile clicks and rubber stamp thuds).

## 🚀 Getting Started

### Prerequisites
- **Node.js:** `v20.x` or higher
- **Package Manager:** `npm`, `pnpm`, or `bun`
- Accounts for **Groq**, **Clerk**, and **Vercel KV**

### 1. Clone & Install
```bash
git clone https://github.com/siddongare/inboxsignal.git
cd inboxsignal
npm install
```

### 2. Configure Environment Variables
Create a `.env.local` file in the project root:

```env
# Clerk Authentication
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
CLERK_SECRET_KEY=sk_test_...
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/
NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/
NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/

# Groq Diagnostic Engine
GROQ_API_KEY=gsk_...

# Vercel KV Redis (Optional for local dev — in-memory fallback included)
KV_REST_API_URL=https://...kv.vercel-storage.com
KV_REST_API_TOKEN=...
```

### 3. Run Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

### 4. Production Build Verification
```bash
npm run build
npm run start
```
